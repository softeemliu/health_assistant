# 健康助手（health_assistant）

一个装在 Windows 上、只读优先的本机巡检 + 清理 + 数据恢复工具。
单文件 EXE 交付，不联网、不上传、不装服务。

> 名字里的「只读」不是形容词：数据恢复的整条链路（扫盘、做镜像、导出）**不会往被恢复的
> 那块盘写一个字节**，导出目标强制要求是另一块盘。

## 能做什么

**巡检与体检**

- 19 项检查项：系统概况、CPU/内存、磁盘容量、硬盘 SMART、启动项、后台常驻进程、
  系统更新、安全中心状态、驱动异常、网络与 DNS、浏览器主页劫持、弹窗来源……
- 每项只给三种结论：正常 / 建议处理 / 必须处理，并说明判断依据
- 支持 `--full` 出明细报告（Markdown），修复命令带绝对路径可直接粘贴执行

**清理与瘦身**

- 系统垃圾、临时文件、更新缓存、浏览器缓存、聊天软件缓存（清理前明确提示先备份聊天记录）
- 大文件 / 重复文件定位，磁盘占用下钻
- **清理台账**：每次删了什么都记一笔（`%APPDATA%\health_assistant\clean-ledger-*.json`），
  删错了能回溯

**硬盘与分区**

- 分区容量、文件系统、SMART 健康、通电时长、温度
- 整卷镜像：断点续传 + 坏道跳过（填 0 保长度，位置记进 `.badmap`）+ 镜像前空间与健康预检

**数据恢复（NTFS / FAT12/16/32 / exFAT）**

界面上**只有一个「开始查找」按钮** —— 不需要先判断「文件是进回收站了、被删了、还是盘被格式化了」，
那本来就不该由用户回忆。点下去后台按下面的顺序自动跑一遍，结果合并去重：

> 回收站（秒级）→ 已删除记录（几十秒）→ 格式化残留（几分钟起，只在前面几乎没找到时自动触发）

找出来的结果按「先能原样还原、再能确认内容」排序。表格里同时给出每一档的来源统计，
比如「找到 128 项（回收站 3 项，已删除记录 125 项）」。

各场景下具体走哪条路：

| 场景 | 做法 |
|---|---|
| 还在回收站 | 按原结构还原，最稳 |
| 已删除（NTFS） | 扫 `$MFT` 已删除记录，能带回原文件名和目录 |
| 已删除（exFAT / FAT） | 扫目录项里的已删除条目（exFAT 删除只清 in-use 位，恢复率最高） |
| 格式化之后 | 扫残留记录 + `$INDX` 目录索引 + `$USN` 变更日志，四路按记录号合并 |
| 记录也被覆盖 / 盘被格式化 | 按文件类型在未分配空间里 carving：**23 类 / 30+ 扩展名**，按结构走完整个文件（大视频、大压缩包也切得准），默认扫整个未分配区 |
| 整盘镜像（0 偏移是分区表） | 解析 MBR/GPT 自动定位分区；分区表丢了可按引导扇区签名找回来 |
| 虚拟盘（VHD / VHDX / VMDK） | 直接拖进「打开已有镜像」，动态盘/稀疏盘内部有块映射表，工具自己解开 |
| 取证镜像（E01） | 直接打开，**分卷（.E01/.E02/…）同目录自动凑齐**，压缩块逐块解压校验；Ex01 / L01 / QCOW2 会告诉你是什么格式、怎么转 |

细节上做了这些：

- **评级不给假希望**：`good` 只能来自「解压/读出的文件头魔数对得上」；没有判据就报
  「看着还在，但确认不了」，数据区全零报「已被清零」。压缩、EFS 加密、只有名字的条目
  **一律拒收**，不导出打不开的文件
- **NTFS 压缩（LZNT1）真解包**，ADS（`Zone.Identifier` 等命名流）单独列出并导出
- **碎片文件尽量拼回去**（4.19.0）：
  - 文件系统还记得段表的（NTFS `$MFT`）→ **按 runlist 多段精确拼接**，拼出来逐字节
    等于原件；runlist 长到一条 1KB 记录装不下、被拆进 `$ATTRIBUTE_LIST` 扩展记录的，
    也照样补全，不会只恢复出前半截
  - 只剩内容的（carving）→ 按格式各自处理：MP4 的 `moov` 被切到后面时找回来、
    中间缺的那一小段**按空白补**（不能跳过 —— `stco` 记的是绝对偏移，挤掉缺口视频
    就打不开了）；ZIP 目录区被覆盖时按本地文件头照样把内容交出来；JPEG 熵编码区
    **中间断掉数学上接不回去**，但会识别出「这里是别人的文件内容」并切在缺口之前，
    不再把别人的数据拼进照片还报「完整」
- **列表不再悄悄截断**（4.20.0）：一键查找、已删除记录、格式化残留三条路都是**全量返回**
  （实测一块盘上残留 16 万条），界面每批 2000 行分批加载，能一直翻到全部；
  没逐条核对过内容的标「还没核对」，点开哪条就核对哪条 —— 不冒充「能完整恢复」
- **`$MFT` 记录大小按记录自己算**（4.20.0）：1KB / 2KB / 4KB 记录都认。以前写死 1KB，
  格式化时选过 4K 记录的卷上**每一条记录都校验不过**，整卷扫出来是 0 条还不报错
- **扫描并行读盘**（4.21.0）：核对内容、拼原路径这两步是「一次随机小读 + 一点解析」，
  串行时 CPU 全在等盘。改成多线程并行（最高 8 路，实测随机 4KB 读 6.3k → 44k 次/秒）：
  一块 1900GB 的盘、全量 15.8 万条记录，**79 秒降到 22~27 秒**。`$USN` 变更日志的解析
  也顺手优化（先判事件类型再解文件名，250 万条约 5.2 → 2.8 秒）
- **边扫边出结果**（4.22.0）：扫一块盘 20~90 秒、格式化恢复几分钟，以前这段时间列表是空的，
  只剩一句「正在查找…」，用户不知道盘里到底有没有东西。现在是**扫到就列出来**（攒 256 条
  或 0.35 秒发一批，增量追加行、不重建表格），实测 C: 全量 15.8 万条时**第 2.7 秒**就出第一条、
  总共 50 秒；这些行的评级写「刚扫到，还没核对」，扫完整体换成核对过的结果 —— 不冒充「能恢复」
- **恢复后自检**：比对大小、文件头、是否全零，不通过的单独标出来
- **按类型找（carving）按结构校验**：PNG 走 chunk 链、ZIP 校验中央目录偏移、7z 校验
  StartHeader 的 CRC、EXE 走节表、TIFF 走 strip 表……签名之后结构必须自洽，
  随机数据里「碰巧像某个文件」的垃圾进不来；每种类型还有各自的体积上限，
  不会把一个 4GB 的假文件写到用户盘上
- 扫描结果能存成 `.pcirc` 存档，几小时的整卷扫描不会关掉就没

**其他**

- 网络急救（DHCP / DNS / 代理 / hosts / Winsock）、FTP 上传下载、凭据管理、弹窗治理

## 怎么跑

**直接下 EXE**（推荐给普通用户）

从 Releases 下载 `健康助手.exe`，双击即可。单文件、免安装、无控制台窗口。

**从源码跑**

```bat
pip install PySide6 psutil
python health_assistant_app.py
```

或者双击 `启动健康助手.pyw`（用 pythonw 启动，不会闪黑框）。

**命令行**

```bat
health_assistant.cmd list
health_assistant.cmd system --full
health_assistant.cmd clean
```

`health_assistant.cmd` 内部会 `pushd` 到自己所在目录，所以在任何目录下粘贴都能跑
（包没有装进 site-packages，直接 `python -m health_assistant` 只在项目根目录有效）。

## 目录结构

```
health_assistant/            源码包
  checks/                    19 个检查项，按分组注册
  gui/                       PySide6 界面（页面 / 后台任务 / 主题 / 控件）
  recovery.py                NTFS 恢复：MFT / $INDX / $USN / 修复 / 镜像 / 导出
  fatfs.py                   FAT12/16/32 与 exFAT 的目录项解析
  partitions.py              MBR / GPT 解析、按引导扇区签名找回分区
  vdisk.py                   VHD / VHDX / VMDK / E01 虚拟盘与取证镜像 → 扁平字节流
  lznt1.py                   NTFS 压缩解包
  catalog.py                 扫描结果存档（.pcirc）与筛选
  smart.py  metrics.py  ...  采集层
health_assistant_app.py      入口（判断源码/冻结，带参数进命令行模式）
health_assistant.cmd         CLI 包装脚本
启动健康助手.pyw              双击入口（无控制台窗口）
tools/                       图标生成、控制台启动器
plugins/                     插件目录（放 .py 自动加载）
```

## 依赖与构建

- Python 3.11+（实测 3.13）
- `PySide6`、`psutil`（其余全是标准库）
- 打包：PyInstaller `--onefile --windowed`，产物约 53 MB

## 免责声明

- 数据恢复**不承诺恢复率**。SSD 开了 TRIM、簇已被新文件占用、EFS 加密、NTFS 压缩
  这几类情况，软件层面读不回来，换什么工具都一样 —— 工具会如实告诉你，而不是给你一个
  打不开的文件。
- 误删之后**先停止往那块盘写任何东西**，再做镜像、再扫。
- 清理功能会删文件（虽然记台账、且可回收到回收站），删之前请自己确认。
